## Imports e aliases resolvidos

`AuthContext` usa o cliente global para Auth e descoberta autorizada. `CompanyScopeContext` mantém fallback público bloqueado pela boundary para usuários autenticados sem contexto. `useSalmonStore` e `EstoqueGeralView` têm helper Auth externo e `supabase` local sombreado vindo de `useSupabase`: substituir o import sem olhar o símbolo quebraria o helper. `tenant.ts` e `permissions/hooks.ts` importam somente tipos; telemetria legada recebe client contextual e chave userId/companyId. Helpers de apresentação recebem o client no parâmetro. O inventário guarda declaração e linha, não só busca textual.

## Residuais F10

1. As proteções de lifetime não resolvem toda concorrência de filtros dentro da mesma montagem; conferir gerações por tela se um caso for reproduzido. Não usar essa observação como prova de vazamento entre tenants.
2. Exportadores de outros módulos com trabalho assíncrono não receberam certificação completa de cleanup; apresentação/atas foram o foco demonstrado. Toast suprimido não cancela geração de documento por si só.
3. Guards de backend ausentes ou incompatíveis continuam bloqueando publicação coordenada. A UI protegida não substitui RLS/RPC/ACL.
4. Preferência obsoleta usa a mesma validação por inclusão que a forjada; browser verificou forjada, componente cobre seleção/fallback. Empresa inativa/membership inactive foram verificadas por HTTP; revogação também no browser.
5. A fixture browser usa roles distintas A admin/B viewer e ALLOW granular com DENY legado. Isso não replica todos os perfis produtivos nem todos os dados de planejamento/atas.
